# 任务意图路由

先判断任务的主要意图，再加载对应参考文件。一个任务可以叠加多个路由，但只保留必要的流程。

| 任务信号 | 主路由 | 必须产物 | 关键门禁 |
|---|---|---|---|
| 只想了解仓库或可行性 | `discover` | 上下文摘要或探针结果 | 不修改仓库 |
| 新功能、需求含糊、跨模块设计 | `specify` | 目标、边界、成功标准 | 先确认关键假设 |
| 已有明确方案，需要拆任务 | `plan` | 可执行任务表 | 每项有文件、验证和完成条件 |
| 多文件功能或重构 | `implement` | 增量切片记录 | 每个切片都可运行、可验证 |
| Bug、测试失败、异常行为 | `debug` | 复现步骤、根因假设、验证结果 | 未定位根因前不改代码 |
| 代码评审或外部评审意见 | `review` | 按严重性排序的发现 | 先核对仓库事实，再决定是否采纳 |
| 准备交付、提交或发布 | `ship` | Definition of Done 证据包 | 未运行的检查不能标记为通过 |
| 优化当前 Skill | `evolve` | 基线、测试提示词、改动提案、复核结果 | validation-gated，失败则回滚 |

## 路由规则

1. `S` 级单点修改可使用“变更卡”：目标、非目标、验收命令和风险各写一句。
2. `M/L` 级任务先使用 `specify` 或 `plan`，不得一边猜测一边实现。
3. 任务中出现失败、回归或异常行为时，切换到 `debug`；不要继续叠加未经验证的修复。
4. 任务进入交付阶段时始终叠加 `ship`，即使实现本身很小。
5. 路由只决定加载哪些流程，不改变安全、项目规则、架构和语言规范的优先级。

`review` 路由必须加载 [代码评审](review.md)；`debug` 路由必须加载 [系统化调试](debugging.md)。
`evolve` 路由必须加载 [Skill 演化协议](evolution.md)，并运行 `scripts/skill_health.py`。
