# 代码评审

评审优先报告问题，不先写总结或表达认可。每个发现都要绑定文件、行号、影响、证据和建议动作。

## 评审顺序

1. 先读完整 diff、任务目标和项目规则。
2. 按 `P0`（阻断/安全）、`P1`（高风险）、`P2`（一般问题）、`P3`（低风险建议）排序。
3. 检查行为回归、错误处理、边界条件、权限/数据泄露、测试缺口、注释同步和无关改动。
4. 对外部评审意见先在仓库中复核；技术上不成立时说明证据和取舍，不盲目照改。
5. 修复一个问题后运行对应定向验证，再处理下一个问题。

## 评审输出

```text
finding: [P1] <问题>
location: <path:line>
impact: <可观察影响>
evidence: <代码、测试或命令>
recommendation: <最小修复或需要人工决策>
```

没有发现问题时，仍说明检查范围、验证命令和剩余测试缺口；不要把“没有发现”写成“绝对没有风险”。
