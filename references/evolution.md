# Skill 演化协议

Coding with Memory 的“自进化”分为两条隔离链路：

```text
任务反馈/失败轨迹 -> Memory 候选 -> 人工或回放批准 -> 后续任务检索
Skill 修改提案 -> 基线检查 -> 受控验证 -> 人工确认 -> 保留或回滚
```

Memory 可以积累协作偏好和工程经验，但不能直接改写语言规范、安全规则、架构边界或质量门禁。Skill 本身的修改必须经过版本化审查。

## 四层结构

| 层 | 回答的问题 | 可变内容 | 保护措施 |
|---|---|---|---|
| `context` | 当前仓库和任务是什么 | 上下文摘要、项目覆盖 | 只读收集，证据来自仓库 |
| `method` | 应该怎样计划和实现 | 工作流、语言路由、注释规则 | 强制规范优先，人工评审变更 |
| `verification` | 怎么证明完成 | 门禁、测试提示词、证据包 | 实际命令、退出码、失败记录 |
| `memory` | 什么经验值得复用 | 候选偏好、模式、事故 | 脱敏、作用域、审批、可停用 |

## 受控演化循环

每轮只处理一个明确短板，避免“改了很多但不知道哪一处有效”：

1. **基线**：运行 `scripts/skill_health.py`，读取 `assets/evolution/test-prompts.json`，记录当前结果。健康检查只发现结构缺口，不是质量总分。
2. **提案**：说明待改文件、失败证据、预期改善和不变约束；禁止直接覆盖旧版本。
3. **单变量编辑**：优先修改一个参考文件或一个主流程段落；不顺手重排整个 Skill。
4. **验证**：重新运行健康检查；先用 `development` 提示词迭代，再用未参与修改的 `holdout` 提示词检查计划、验证、边界和 Memory 隔离行为。
5. **独立复核**：编辑者不作为唯一评审者；至少由另一轮 Agent 或人工按同一验收标准复核。
6. **棘轮决策**：只有在没有回归且证据显示不变或改善时保留；否则恢复到上一个已批准版本。优先使用可审查的 Git 回滚，不使用破坏性重置。
7. **人工检查点**：涉及强制规范、安全、架构或触发行为的变更必须等待维护者确认。

## 不允许的演化

- 用单次 LLM 评分决定保留或回滚。
- 同一个 Agent 同时提出修改、证明修改有效并批准修改。
- 用绝对分数的小幅上涨掩盖测试回归、冗余增加或边界丢失。
- 把候选 Memory 自动晋级为 `approved`，或把偏好写入规范文件。
- 在没有测试提示词、基线或回滚点时修改 Skill。
- 为通过静态健康检查而堆叠关键词、重复段落或无效检查点。
