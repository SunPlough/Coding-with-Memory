# 通用工程基线

这些规则适用于所有编程语言。

## 必须遵守

- 采用满足明确需求的最小完整变更。
- 匹配仓库已有结构、命名、错误模型、日志方式和测试惯例。
- 一次变更只处理一个逻辑关注点；功能开发与无关重构分开。
- 在输入、I/O、网络、持久化、并发和外部 API 边界显式处理失败。
- 不记录密钥、令牌、凭据、个人数据或完整敏感请求/响应。
- 为改变的行为和重要边界新增或更新测试，不以提高覆盖率数字为唯一目的。
- 按项目包管理策略锁定或约束依赖，并说明兼容性影响。
- 记录公共 API、迁移、配置和运维行为变化。
- 遵循 [注释规范](comments/index.md)：注释保存契约与原因，不逐行翻译代码。

## 复杂度门禁

- 没有当前用例，不新增抽象、分支、配置、扩展点、重试或回退路径。
- 早返回能减少嵌套并提高可读性时优先使用，但不机械追求分支指标。
- 先保持行为正确，再改进风格；不顺手重写无关代码。
- 小型重构能消除歧义时，优先改进命名、类型和结构，而不是堆叠解释性注释。
- 新通用层至少说明两个当前、稳定且真正重复的使用场景。
- 通用建议与仓库规则冲突时遵循仓库规则，并记录原因。

## 验证

运行变更路径适用的格式检查、Lint、类型/构建、测试和安全/依赖检查。所有格式化器必须使用检查模式；报告跳过、未发现和失败的检查及原因。
