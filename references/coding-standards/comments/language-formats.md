# 各语言注释格式

本文件只负责路由。仓库 Formatter、Lint、文档生成器和当前语言的 Google/官方规范仍是格式权威。

| 语言 | 公共/API 文档 | 内部原因 | 注意事项 |
|---|---|---|---|
| C | 项目选定的 Doxygen 或头文件惯例 | `//` 或项目形式 | Google 无专门 C Guide，不要直接套用 C++ 规则。 |
| C++ | Google C++ 头文件/注释惯例；仅在配置时使用 Doxygen | `//` | 记录所有权、生命周期、线程安全和非显然不变量。 |
| C# | 项目要求时使用 XML 文档 `///` | `//` | 保持 XML 标签有效，不机械重复签名类型。 |
| Dart | Dart Doc `///` | `//` | 先写简洁契约，由生成文档结构决定细节。 |
| Go | 以导出标识符开头的 Go Doc | `//` | 标识符保持原文，即使说明使用中文。 |
| HTML | 项目文档或相邻 Markdown | `<!-- -->` | 不在注释中保留秘密、数据或废弃标记。 |
| CSS/SCSS | 项目选定的 Stylelint/SassDoc 形式 | `/* ... */` | 解释浏览器限制、Token 或层叠原因，不复述声明。 |
| Java | Javadoc `/** ... */` | 项目约定的 `//` 或 `/* ... */` | 非显然时记录公共契约、异常、副作用、泛型和枚举含义。 |
| JavaScript | 项目生成文档或纯 JS 需要契约/类型时使用 JSDoc | `//` | TypeScript 已表达的类型不要在 JSDoc 重复。 |
| TypeScript | 已配置或公共契约需要文字语义时使用 TSDoc/JSDoc | `//` | 类型表达形状，注释表达语义和约束。 |
| JSON | 无 | 无 | 严格 JSON 不支持注释，改用 Schema 或文档。 |
| JSONC | 工具支持的 `//` 或 `/* ... */` | 同左 | 先确认消费者支持 JSONC。 |
| Kotlin | KDoc `/** ... */` | `//` | 类型已表达的可空性不要机械复述。 |
| Objective-C | 项目采用的头文件文档形式 | `//` | 明确所有权、Nullability 和 API Availability。 |
| Python | 仓库采用的 Google-style Docstring | `#` | Docstring 描述契约，不机械重复类型标注。 |
| R | 配置时对导出 API 使用 Roxygen2 `#'` | `#` | 记录向量化、缺失值、单位和副作用。 |
| Shell | 仅在仓库要求时使用函数/文件头注释 | `#` | 解释破坏性操作、可移植性、引用假设和退出行为。 |
| Swift | Swift Doc `///` 或 `/** ... */` | `//` | 记录 Actor/线程、所有权和可用性约束。 |
| Lisp | 方言/项目文档形式 | `;`、`;;` 或方言形式 | 先确认方言再选择注释级别。 |
| Vimscript | 项目/Vim Help 惯例 | `"` | 明确兼容性和副作用。 |
| XML | Schema 或外部文档 | `<!-- -->` | XML 声明之前不得放注释，保持 Schema/工具规则。 |

除非仓库政策或生成工具明确要求，不添加 `@author`、创建日期、变更日志或文件头。版本控制默认负责作者与历史。
