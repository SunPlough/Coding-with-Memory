# Agent 开发工作流

## 开始前

- 先读取仓库事实，再形成方案；仓库中的规则、代码和可执行配置高于模型假设。
- 只打开与当前路径、语言、框架和风险相关的参考文件，不一次加载全部规范。
- 区分目标、非目标、验收条件和风险。无法从仓库安全确定且会实质改变结果的选择，再请求用户决策。

## 实现中

- 保持补丁小、完整、可审查，不把无关清理混入功能修改。
- 复用已存在的边界、错误模型和测试模式。新增抽象前指出当前调用方与当前收益。
- 每次行为变化都对应测试或其他可观察验证；先修实现，不为了让测试通过而弱化断言。
- Bug 或行为变化优先先写能证明问题的失败测试/最小探针；配置、文档和一次性探针可采用定向检查，但必须说明例外。
- 注释只保存契约、约束与原因，并在实现变化后同步复核。
- 发现用户或其他 Agent 的并行变更时保留它们；有重叠则重新读取并协同修改。

## 验证与交付

- 每个“已通过”结论都必须能追溯到本次实际运行的命令和结果。
- 区分通过、失败、跳过和未发现，不把未运行的检查描述为通过。
- 交付时说明范围、验证、剩余风险、回滚方法和 Memory 使用情况。
- 把反馈、失败原因、成功路径和候选偏好分别记录；不得让 Memory 静默改变强制规范。
- 评审发现按严重性排序，并逐项绑定路径、证据和验证结果；外部建议先核对仓库事实。
