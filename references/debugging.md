# 系统化调试

遇到 Bug、测试失败、构建失败或异常行为时，先找根因再修复。简单问题也遵循同一顺序，但可以压缩记录。

## 四阶段

1. **复现与收集**：完整读取错误、记录精确命令和输入，确认是否稳定复现；检查最近 diff、环境和依赖。
2. **定位与对比**：沿数据流回溯坏值来源；寻找同仓库中正常工作的相似路径，列出差异。
3. **单一假设**：写出“我认为根因是 X，因为证据 Y”；用最小探针或失败测试验证一个变量。
4. **修复与回归**：只修根因，先确认回归测试失败再实现，验证通过后运行受影响的完整门禁。

## 停止条件

- 尚未复现或没有证据时，不提交猜测性修复。
- 每次只验证一个根因假设；失败后回到阶段 1，不在同一补丁中堆叠修复。
- 连续三次假设失败时暂停，评估是否存在架构或边界问题，并请求人工决策。
- 修复过程中发现与当前问题无关的清理项，只记录，不顺手修改。
